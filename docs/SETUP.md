# Setup and troubleshooting

This guide starts from a fresh clone. AegisWallet runs on Base Sepolia (84532), on one local Node process. You do not need a browser wallet extension. Use test assets only.

## 1. Prerequisites

- Git, Node.js **24.15 or newer within the 24.x release line**, and **pnpm 11.25.0**. CI uses Node 24; `package.json` pins pnpm. The test toolchain requires at least 24.15 on this release line.
- Internet access to install dependencies and read Base Sepolia. Offline tests use mocked chain calls or an in-process EVM.
- A writable checkout for `.env.local`, `data/` and Next.js output. Local agent instructions and MCP settings are not required.

Confirm `node --version` and `pnpm --version`, then:

```powershell
git clone https://github.com/electr0x0/aegis-wallet.git
cd aegis-wallet
pnpm install --frozen-lockfile
```

Do not copy the submitting team's private environment or point a new installation at its funded guard. Setup generates your own keys; the public addresses in the evidence docs are for verification.

## 2. Start without funding or an LLM

```powershell
pnpm setup-wallets
pnpm dev
```

Open **http://127.0.0.1:3000**, using that same address throughout the session. No manual copy of `.env.example` is necessary. On a fresh checkout, `setup-wallets`:

1. Creates missing agent and vault/owner keys in ignored `.env.local`, without printing secrets.
2. Prints their public addresses and adds your vault address to the local policy whitelist.
3. Reads live funding. With no funds, it reports funding required and exits; it still leaves the wallet ready for the dashboard.

If live RPC reads fail, key creation remains complete and the script reports the unavailable funding check. Restore RPC access for live balances and simulations. No fake balance or transaction is substituted.

On an **existing funded wallet**, `setup-wallets` also attempts a 0.50 USDC vault transfer and a 0.0002 ETH wrap through the regular policy path when the holder has at least 0.0003 ETH and 0.5 USDC. It does not auto-repeat a confirmed, submitted, reserved or pending step. It is not a general read-only health command; do not rerun it merely to refresh balances.

Your new wallet initially uses **EOA mode**: no on-chain guard yet. Command Center shows actual balances, including zeros, and Execution Evidence starts empty. You can explore all views, import the submission JSON in Judge proof, and run tests without funding. A write simulation may fail honestly for insufficient funds.

### Accounts and PINs

The default account is **Master Demo Treasury (Pre-Funded)**, bound to your `AGENT_PRIVATE_KEY`. Its display name does not guarantee funding. Its demo operator PIN is **884210**, available through the master-only quick-fill button.

Provisioning a new account asks for a name, risk preset and six-digit PIN. Presets use $1/$2/$10 single-payment limits and $5/$10/$50 daily limits. Switching requires that account's PIN; unlocked sessions expire after 30 minutes or a server restart. Every Tier 2 approval and policy save needs a fresh PIN. Five failed checks trigger a five-minute lockout.

Generated accounts encrypt their keys using scrypt and AES-256-GCM and operate in EOA mode. The optional one-time 0.0003 ETH gas drip requires the master EOA to hold strictly more than 0.002 ETH and still pass policy, budget, simulation and reserve checks. It does not supply USDC or guarantee successful funding. There is no automatic retry.

Keep `.env.local` and private `data/` records together in private backups. The master PIN is public and the owner key remains on the server; these are prototype controls, not production custody or tenant isolation.

### Core environment settings

| Setting                              | Purpose                                                                                            |
| ------------------------------------ | -------------------------------------------------------------------------------------------------- |
| `AGENT_PRIVATE_KEY`                  | Server-only agent key, guard session key and ledger signer; generated by setup                     |
| `VAULT_PRIVATE_KEY`, `VAULT_ADDRESS` | Matching owner key and vault destination; generated by setup; the key stays on the server          |
| `GUARD_ADDRESS`                      | Optional; deployment writes it. Blank means EOA mode; an invalid value is an error, not a fallback |
| `SESSION_HOURS`                      | New/renewed guard session lifetime; default 24 hours                                               |
| `BASE_SEPOLIA_RPC_URL`               | Optional Base Sepolia endpoint; default `https://sepolia.base.org`                                 |
| `AEGIS_BUILD_DIR`                    | Optional Next.js build-output directory; default `.next`                                           |

For a fresh setup, do not set only `VAULT_ADDRESS` to someone else's address: guard deployment also needs the matching owner key. Keep both generated values together.

## 3. Optional model configuration

Edit `.env.local` without replacing its generated keys. Use only provider keys you control. `.env.example` lists the supported settings:

| Variable                             | Use                                                                              |
| ------------------------------------ | -------------------------------------------------------------------------------- |
| `DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL` | Primary provider; default model `deepseek-flash`                                 |
| `GEMINI_API_KEY`, `GEMINI_MODEL`     | Fallback through the OpenAI-compatible endpoint; default `gemini-3.5-flash-lite` |
| `OPENAI_API_KEY`, `OPENAI_MODEL`     | Final fallback; default `gpt-4.1-mini`                                           |

Only configured providers are tried. Fallback happens on a failed initial planner request; later rounds remain with the responding provider. The invoice reader uses the same provider order. Provider/model presence in Judge proof is configuration, not a health check.

Without a model key, the built-in scenarios, simple transfer/wrap instructions, portfolio reads, address audits and labelled invoice parsing use deterministic code. Free-form/multi-step planning requires a configured provider. Restart the dashboard after changing `.env.local`.

## 4. Fund your own Base Sepolia guard demo

Skip this section if you only need source review, offline tests, or submitted-evidence verification. The following commands deploy contracts and move real **testnet** assets.

1. Stop the dashboard before running operator scripts; the ledger mutex protects only one process.
2. Fund the **agent address printed by setup**, on **Base Sepolia**, with test ETH. For the recipe below, obtain **more than 0.015 ETH**, leaving additional ETH for contract deployment and subsequent agent gas. Optionally send test USDC for token/invoice payments. ETH and native gas on Ethereum Sepolia are a different network.
3. Rebuild the committed guard artifact, then deploy and fund:

   ```powershell
   pnpm guard:compile
   pnpm guard:deploy --eth 0.015
   ```

   Deployment writes your own `GUARD_ADDRESS` to `.env.local`, initializes the expiring session key, and moves 0.015 ETH plus the agent's available USDC into it. Use `--usdc <amount>` to limit the token amount. The default ETH amount without `--eth` is only 0.002; the documented runway floor may hold payments at that funding level. The agent EOA needs its own remaining ETH for gas; guard funds do not sponsor it.

4. Start `pnpm dev` again. Portfolio & Runway should show **AgentGuard treasury**, the session status, holder balances, and the separate agent gas balance. Confirm that the policy, runway and budgets permit the action you intend to demonstrate.
5. Inspect the portfolio, then try the built-in wrap or vault-transfer chip. The transfer chooses available USDC, WETH or ETH; a chip is a proposal, not a guarantee of Tier 1. A failed simulation remains a hard block. The [demo script](DEMO_SCRIPT.md) explains funding and runway requirements for its longer sequence.

A faucet may ask for browser-wallet login or impose eligibility/rate limits. That is a faucet requirement, not an AegisWallet requirement. Test ETH can instead be sent to your printed address by another funded Base Sepolia wallet. No funds are necessary to inspect the submitted receipts or run the offline tests.

### Manage the guard while the dashboard is stopped

```powershell
pnpm guard:deploy --fund-only --eth 0.002
pnpm guard:deploy --renew
pnpm guard:attack
```

`--fund-only` transfers additional test funds. `--renew` changes the on-chain session; after a revoke, the owner must send the renewal and needs ETH at the owner/vault address. `guard:attack` only simulates the three direct compromised-key attacks. Adding `--broadcast` deliberately sends an expected reverted attack and spends gas; it is optional, not a setup step.

`pnpm guard:deploy --revoke` is the owner-authorized on-chain emergency stop. A local dashboard pause blocks application writes but cannot stop a stolen session key outside the application. `--force` creates a different guard; it does not recover funds from the previous instance. See [security section 4.1](05_SECURITY_SELF_ASSESSMENT.md#41-emergency-stop-and-recovery) before using these operations.

## 5. Tests and production build

```powershell
pnpm test
pnpm typecheck
pnpm build
pnpm attacks
```

Tests do not need `.env.local`, model keys, funding, or a running dashboard. Contract tests run the committed artifact on an in-process EVM; they are not live-chain proof. CI runs the frozen install, tests, TypeScript and credential-free production build.

To run a production build locally, stop the dev server, run `pnpm build`, then `pnpm start`. Both server commands bind to loopback. Do not deploy this JSON-backed prototype behind a public proxy, a serverless host or multiple Node workers. For an isolated build beside an existing dev session, set `AEGIS_BUILD_DIR=.next-verify`; that is a build-output setting, not a second dashboard process.

## 6. Verify evidence without installing a wallet

Use the [judge walkthrough](JUDGE_WALKTHROUGH.md#verify-the-submitted-export) for the submitted file, independently supplied signer/guard addresses and the distinction between historical runs. The CLI verifier needs no signing keys and does not import the runtime store. It does not automatically load `.env.local`; for a custom RPC, set `BASE_SEPOLIA_RPC_URL` in your shell.

For your own recordings, use Execution Evidence → Export. Display filters do not restrict the exported account history. Keep the matching signed JSON with the reported signer. Never combine account exports into a claimed complete ledger or replay a transaction because its outcome is unknown.

## Troubleshooting

| Symptom                                          | Check / resolution                                                                                                                                                                                                                                   |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm` missing or wrong version                  | Install pnpm 11.25.0; confirm `pnpm --version`. Do not create an npm/yarn lockfile.                                                                                                                                                                  |
| Install reports a frozen-lockfile mismatch       | Confirm you are on the submitted commit and using the pinned pnpm version. Do not regenerate the lockfile just to suppress the error.                                                                                                                |
| Missing `AGENT_PRIVATE_KEY`                      | Run `pnpm setup-wallets` in the repository root, then restart the server. Never paste a private key into chat or the browser.                                                                                                                        |
| `VAULT_ADDRESS does not match VAULT_PRIVATE_KEY` | Restore the matching private configuration from your backup. Do not generate a replacement owner key for an existing guard.                                                                                                                          |
| Zero portfolio or empty evidence                 | Expected for a fresh wallet. Fund your own addresses for live execution; import the submission JSON for read-only review.                                                                                                                            |
| API rejects the origin                           | Open `http://127.0.0.1:3000` directly. Use the same origin for browser and API; avoid proxies or mixing `localhost` and `127.0.0.1`.                                                                                                                 |
| Port 3000 is occupied                            | Stop the other dashboard before starting this one; do not run two writers against the same `data/`.                                                                                                                                                  |
| RPC unavailable / wrong chain                    | Set a Base Sepolia endpoint in `.env.local` and restart. Chain ID must be 84532; wrong-chain calls are blocked.                                                                                                                                      |
| Holder has ETH but broadcast has no gas          | In guard mode, the agent EOA pays gas separately from guard-held funds. Check both balances.                                                                                                                                                         |
| Small transfer becomes Tier 2                    | Inspect always-ask, local pause, whitelist, remaining daily spend and runway reasons. The committed $8,990 fiat profile is an operator-entered demo assumption. Review truthful inputs; do not weaken controls merely to force an autonomous result. |
| Guard session expired or revoked                 | Stop the server and use `pnpm guard:deploy --renew`. A revoked session requires owner gas; follow the script's named funding address.                                                                                                                |
| PIN rejected / account locked                    | Master demo PIN is 884210; custom accounts use their own PIN. Wait out the five-minute lockout after five failures.                                                                                                                                  |
| No final streamed reply / unknown broadcast      | Inspect Execution Evidence and the returned BaseScan hash before resubmitting. Closing a browser does not cancel a reserved server operation.                                                                                                        |
| Evidence file not found                          | Download the JSON from the submission folder and pass its actual path, in quotes if it contains spaces. Private ledger files are intentionally absent from Git.                                                                                      |
| Evidence has account-filter gaps or EAS mismatch | Confirm you have the matching export/full ledger for that run. Gaps and unanchored tails are limitations, not errors to hide by editing evidence.                                                                                                    |

Architecture details are in [01](01_TECHNICAL_DOCUMENTATION.md); security boundaries and the complete risk list are in [05](05_SECURITY_SELF_ASSESSMENT.md).
