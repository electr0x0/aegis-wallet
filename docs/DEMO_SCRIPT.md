# Demo script

This script covers the recorded demo video (Deliverable 03, optional, 5 minutes or less) and the live final (10 minutes or less). It also includes the deck outline (Deliverable 02), the submission checklist and the registration-form proposal summary. Every prompt below is copied from the scenario cards in `src/components/wallet/scenarios.ts`, and every invoice from `src/components/wallet/invoices.ts`, so clicking a card sends exactly that text.

**Ground rule:** show only what the chain and the app return. You may cut waiting time in the video, but never edit, stage or overlay a balance, hash or status.

## 1. Before recording

1. **Checks pass.** `pnpm test`, `pnpm typecheck` and `pnpm build` all pass.
2. **Guard mode is active.** In Command Center the portfolio card is titled "AgentGuard treasury" and reads "Base Sepolia · Contract custody". The navbar reads "Tier 1 Session Key: ACTIVE". If it says "Server EOA", `GUARD_ADDRESS` is missing from `.env.local` or the dev server was not restarted after it was added.
3. **The guard is funded.** Every demo payment is simulated from the guard and fails if the guard is short. One full run needs:
   - at least **0.0002 ETH** for the Demo 1 wrap (0.0003 ETH if you also do the optional emergency stop, and add the planner wrap if you run that segment)
   - at least **3 USDC**: 1 USDC to the vault in Demo 1 and 2 USDC in Demo 2, or **4.5 USDC** with the 1.5 USDC invoice payment in Demo 5
   - gas ETH on the agent EOA, shown as "Agent gas balance"

   Each rehearsal spends the same amounts again. Top up with `pnpm guard:deploy --fund-only --eth <amount> --usdc <amount>`.

4. **The session is live.** The "Custody & session guard" card in Portfolio & Runway shows "…h …m left", not "expired". Otherwise run `pnpm guard:deploy --renew`.
5. **Budgets have room.** The "24h Auto Budget" telemetry value is well below $50. Earlier rehearsals within 24 hours count toward it.
6. **The runway is calibrated (required).**
   - The committed profile ($8,990 fiat reserve) assumes more on-chain holdings than the guard has after the evidence runs. With about $11 in the guard, even Demo 1's 1 USDC transfer falls just below the 3-month floor and is held for approval (ledger entry 39, 19 October 2026).
   - The Demo 2 runway reason appears only if (fiat reserve + on-chain holdings − $1 − $2) / $3,000 is below 3 months. The $1 is Demo 1's vault transfer, which has left the guard by then.
   - Demo 1's 1 USDC transfer must stay at or above the floor.
   - Both hold when _fiat reserve + on-chain holdings_ is at least $9,001 and below $9,003.
   - Read "On-chain holdings" on the Reserve Runway tile and set `treasury.fiatReserveUsd` in `data/policy.json` to **9,002 minus that figure**. The file is read on every request, so no restart is needed. Restore the committed $8,990 afterwards.
   - Without this step, Demo 1's vault transfer may be held instead of running autonomously.
7. **The ledger is green.** The Execution Evidence view shows "Ledger verified · N sealed".
8. **Windows are ready.**
   - Browser at `http://127.0.0.1:3000`, zoomed so the approval card is legible.
   - A terminal at the repository root for Demo 4.
   - A BaseScan tab on the guard address.
   - **Never open `.env.local` on screen.**

## 7. Proposal summary (registration form)

AegisWallet lets an AI agent act as a bounded financial participant on Base Sepolia. Operators give instructions in plain language. A language model or a deterministic parser turns them into typed proposals, but it never decides and never signs. A deterministic policy engine places each proposal in a permission tier:

- read-only
- autonomous within single-transaction, rolling 24-hour and cash-reserve-runway limits
- held for human approval

Prompt-injection attempts, blacklisted recipients, failed simulations and excessive gas are blocked outright. Funds are held by AgentGuard, our on-chain session-key contract. The agent's key can reach only allowlisted recipients and call shapes, within per-asset caps. It cannot grant token approvals, and anything else needs an owner signature verified on-chain. These limits hold even if the model or the agent key is compromised; a broadcast attack that the contract reverted demonstrates this. Every decision is recorded with a template-generated rationale, the policy hash, a hash chain and an agent signature, which gives auditors an explainable, tamper-evident trail. The prototype runs on testnet with fixed reference pricing. In production, the owner key would move to a separate device.
